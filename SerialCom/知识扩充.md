**RTS = Request To Send，请求发送**，是 RS232 串口的硬件握手信号（DB9 第 7 脚），一般和**CTS（Clear To Send，允许发送）配对使用，也就是 RTS/CTS 硬件流控**

> ✅ 配套记忆：
>
> - **RTS（Request To Send）**：我方输出 → 告诉对方：**我准备好了，可以收数据**
> - **CTS（Clear To Send）**：我方输入 → 读取对方信号：**对方允许我发数据**接线必须交叉：A 的 RTS → B 的 CTS；A 的 CTS → B 的 RTS

## 📌 两种用途（工业上位机非常常见）

### 1）RTS/CTS 硬件流控（高速串口防丢包）

接收端缓冲区快满时，**拉高 RTS** → 发送端检测到自己的 CTS 拉高，自动暂停发数据；接收端处理完、缓冲区有空了，**拉低 RTS** → 发送端继续传输。

> 作用：解决收发速度不一致导致丢数据，替代你前面写的延时等待方案。

### 2）单纯手动控制电平（485 半双工最常用！重点！）

很多 **RS485 转串口模块** 直接复用 RTS 引脚控制收发方向：

- RTS 高 → 485 芯片进入**发送模式**
- RTS 低 → 485 芯片进入**接收模式**

> 这个是工业上位机最常碰到的场景！你写 485 Modbus RTU 时经常要手动控制 RTS 电平。

## 📌 C# SerialPort 里的属性

```
// 手动设置RTS电平
_port.RtsEnable = true;  
// 开启自动RTS/CTS硬件流控（驱动自动管理RTS，不要手动改RtsEnable）
_port.Handshake = Handshake.RtsEnable;
```

> ⚠️ 注意：一旦设置 Handshake.RtsEnable，系统自动接管 RTS，自己手动修改 RtsEnable 会失效

## 📌 和你之前知识点串联

1. **普通 RS232 仪表（CRLF 结尾）**：绝大多数不用 RTS/CTS，只 TX/RX/GND 三根线
2. **高速大数据串口**：启用 RTS/CTS 硬件流控，不容易丢包
3. **485 总线（Modbus-RTU）**：几乎都要用 RTS 控制收发切换
4. **TouchSocket/HslCommunication** 都支持自动 RTS 控制

## 📌 补充另外两个常用控制信号（顺带记）

- DTR：Data Terminal Ready 数据终端就绪
- DSR：Data Set Ready 数据设备就绪DTR/DSR 是另一套老握手，现在工业设备很少用，多用于老 Modem。

## ❓ 一句话快速区分

- CRLF：**报文结束标记（字节）**
- RTS：**硬件引脚电平信号（流控 / 485 方向）**
